# G1-SPEC — 会话与上下文工程

> Goal：G1 · 状态：✅ 已完成 · 日期：2026-10-27 · 上游：[AUDIT.md](../AUDIT.md) · 下游：[G1-design](./G1-design.md)
> 目标：会话可搜索/归档/分页，上下文按 token 预算自动裁剪，长对话不失控。

## 1. 问题陈述

当前 `messages.json` 单文件全量读写、历史固定 `slice(-10)`、摘要仅首次生成一次。会话超过几百条后面板变慢、上下文不可控、无法回看/搜索历史。

## 2. 用户故事

- 作为用户，我可以**搜索**历史会话/消息（按 bot、时间、关键词）。
- 作为用户，长会话我只看**最近 N 条**，但能翻页/归档**旧会话**。
- 作为用户，bot 回答时自动把超预算的旧上下文**压缩成摘要**，重要新信息不丢。
- 作为用户，所有内容**保持本地文件可迁移**（不引入外部 DB 依赖即可完成）。

## 3. 功能需求

| # | 需求 | 验收 |
|---|------|------|
| F1 | 会话列表分页/加载更多 | 100+ 会话面板不卡，滚动加载 |
| F2 | 消息分页（增量加载窗口） | 只渲染窗口内消息，旧消息「加载更多」 |
| F3 | 会话搜索（标题/消息关键词/bot/日期范围） | 关键词命中定位到会话与上下文片段 |
| F4 | 会话归档/清理（软归档 + 一键删除） | 归档不进列表；可恢复/可删 |
| F5 | 上下文 token 预算裁剪 | 超预算自动压缩旧消息为 summary 并注入继续 |
| F6 | 会话摘要自动补（增量） | 每达阈值自动压缩，不重复压缩已压缩段 |
| F7 | 消息增量存储（避免全量重写） | 高频消息下 IO 不随总量线性放大 |
| F8 | 兼容现有数据 | 旧 `messages.json` 自动迁移，消息不丢 |

## 4. 非功能

- 性能：10k 消息会话打开 < 1s；搜索 < 500ms（本地）。
- 存储：仍 local-first JSON（可加单文件分片）；迁移格式保持 v2/升级 v3。
- 安全：归档/删除不影响正在运行的任务引用。

## 5. 边界

- 不做向量检索（G2）；不做分布式会话存储。
- 保留现有 `Store` 接口兼容旧 IPC 调用（新增方法，不改签名）。
