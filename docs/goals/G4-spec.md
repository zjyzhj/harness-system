# G4-SPEC — 多 Bot 协作

> Goal：G4 · 状态：✅ 群聊 / 富消息 / 网关已实现 · ❌ 编排器已退役（2026-11，对齐 Grok：群聊 @ / bot.ask） · 上游：[AUDIT.md](../AUDIT.md) · 下游：[G4-design](./G4-design.md)
> 目标：从「两 bot 互发文本」升级为「群组广播 + 富内容互发 + 主控指挥」；多步接力用群聊 `@` 或 `bot.ask`，不再使用流水线编排器。

## 1. 问题陈述

MessageBus 只能两 bot 互发文本；无群组、无广播；HTTP Transport 预留但无服务端，无法跨进程。

## 2. 用户故事

- 作为用户，我建一个**群组**（如「产品组」），一句话 @组 让所有组员 bot 各自回应。
- 作为用户，bot 之间能传**富内容**（图片/文件/工具结果），不是只有文本。
- 作为用户，我让主控「让 A 调研、B 总结、C 写成报告」→ 用群聊接力或依次 `bot.ask` 完成，结果回到对话。
- 作为用户，多个 harness 实例（两台机器）可通过**网关**互联，远程 bot 参与协作。

## 3. 功能需求

| # | 需求 | 验收 | 状态 |

| F3 | ~~编排器（顺序 / fan-out / 汇总）~~ | 由群聊 + `bot.ask` 替代 | ❌ 退役 |
| F4 | ~~编排可视化~~ | — | ❌ 退役 |
| F5 | HTTP 网关（服务端 + 客户端） | 跨进程 bot 通信成功 | ✅ |
| F6 | ~~编排权限：仅主控发起~~ | 群聊权限 / bot.ask 深度限制仍在 | ❌ 退役（编排部分） |
| F7 | 迁移：群组往返；旧 `plans` 忽略 | 导入可跳过编排历史 | ✅ |

## 4. 非功能

- 群聊接力可中断 / 插话 / 轮数上限；发言可审计。
- 网关消息 token 校验；失败可标记。

## 5. 边界

- 不做通用工作流 DAG / 流水线面板（已退役）。
- 不做云端编排服务；网关为本机/局域网自建。
