# GOAL — Harness Bot 管理系统（macOS 桌面端）

> 阶段：Goal · 状态：✅ 已定稿 · 日期：2026-10-26
> 流程：Goal → Spec → Design → Task → 实现

## 1. 背景与动机

你日常使用多套 AI 智能体工具：Codex CLI、Claude Code、Cursor、Grok Bot（桌面端）、GaleHarnessCLI 以及各种 API 中转（url/key）。这些工具各自独立：配置分散、模型不统一、无法互相通信、没有统一的管理面板，也难以把「一个想法」快速变成「一个带形象、能干活、能和其他 bot 协作的智能体」。

我们希望做一个 **macOS 本地桌面端「Harness Bot 管理系统」**——以 xAI Grok Bot 桌面端的对话体验为界面参考，把散落的 CLI / API / bot 统一到一个「主控」里：

- **一句话创建 bot**：像 Grok Bot 一样快速，输入一句话就生成一个智能体（含名字/角色/模型/性格）
- **主控面板**：一个主窗口统一指挥所有 bot，随时对话
- **一句话生成形象**：给任何 bot 一句话生成形象（头像/角色卡）
- **桌面宠物**：bot 以宠物形态活跃在桌面上——常驻、可拖动、可互动（点击对话、气泡提示），像桌面宠物一样
- 多个 bot 之间可以互相通信、协作
- 统一管理模型 url / key（OpenAI 兼容 API、以及 codex / cursor / claude CLI 适配）
- 常驻菜单栏，可调用系统能力（通知/剪贴板/文件）
- 支持配置与 bot 的迁移（导入/导出）

## 2. 一句话目标

> 做一个 local-first 的 macOS 桌面端 AI 智能体指挥中心：像 Grok Bot 一样一句话快速创建 bot、一句话生成形象，bot 作为桌面宠物活跃在桌面上，主控面板统一指挥，多 bot 可通信，统一接入主流 CLI 与模型 API。

## 4. 范围

### In-scope（MVP）
- macOS 本地应用（菜单栏 + 窗口面板 + 悬浮窗）
- 对话面板（Grok-Bot 风格：暗色、左侧会话/bot 列表、中间对话、底部输入）
- bot 管理：一句话创建、编辑、删除、启用/停用
- 形象生成：AI 生成头像 + 角色卡（先用本地/API 图像接口，简单实现）
- 多 bot 通信：进程内消息总线（MVP 不追求跨进程分布式）
- 模型配置中心：统一 url/key/model，按 bot 绑定；OpenAI 兼容 chat completions 调用
- CLI 适配器：codex、cursor、claude（capability 探测 + 调用封装，失败降级为 API）
- 系统能力：通知、剪贴板、文件读写（最小实现）
- 迁移：JSON 导出/导入（bot、配置、会话摘要）

### Out-of-scope（MVP 明确不做）
- 云同步、多人协作、远程访问
- 移动端 / Windows / Linux 客户端
- 分布式多进程 agent 编排（如 ruflo 的 swarm / deer-flow 的长程编排）
- 生产级部署、账号体系、支付/商业化
- 完整原生系统自动化（如 Grok Computer Use 级别的屏幕操控）

## 5. 关键约束

1. **local-first**：配置、bot、会话默认存储在本机（`~/.harness-bot/`），不强制联网登录。
2. **改造优先**：优先在成熟项目上改造（DeepSeek-Harness 的插件化架构 / CowAgent 的多智能体模型 / GaleHarnessCLI 的本地习惯），避免从零造轮子。
3. **许可证合规**：所选上游均为 MIT；保留 LICENSE 与来源声明。
4. **不过度设计**：MVP 用单进程 TypeScript/Bun + Electron 风格壳，不引入分布式中间件。
5. **可迁移**：所有用户数据均可导出为单一 JSON 文件。

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| CLI（codex/cursor/claude）能力差异大 | 适配器做成 capability 探测 + 逐步降级：CLI 不可用时回退 OpenAI 兼容 API |
| Electron 壳与 Bun 运行时集成复杂 | 壳保持薄，核心逻辑独立成 `core/`，UI 只做展示 |
| 形象生成依赖外部图像 API（配额/网络） | 接口抽象化；无网时可先用本地占位图/程序化头像，不阻塞主线 |
| 模型 key 安全性 | 配置存本机文件（权限 0600），导出时 key 可脱敏选项 |
| 范围膨胀（做成 ruflo 级 swarm） | MVP 严守 in-scope，把协作通信限制在进程内消息总线 |
